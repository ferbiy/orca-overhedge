| Інструкція                                   | Для чого                                                                                   |

## Звідки беруться збірки

Кожну збірку викладаємо на сторінку
[Releases](https://github.com/ferbiy/orca-overhedge/releases) цього форку. Інших офіційних джерел
збірок форку немає.

- Тег: `v<версія апстриму>-overhedge.<n>`, наприклад `v1.4.278-overhedge.30`.
- Версія в застосунку чи пакеті: `<версія апстриму>+overhedge.<n>.g<коміт>`, наприклад
  `1.4.278+overhedge.30.gbce58c734d`. Частина `+overhedge` означає, що це збірка форку.

Файли в релізі:

| Файл                                                         | Що це                                          |
| ------------------------------------------------------------ | ---------------------------------------------- |
| `orca-ide_<версія>+overhedge.<n>.g<коміт>_amd64.deb`         | пакет Linux x86_64: і сервер, і десктоп        |
| `Orca-<версія>_overhedge.<m>.g<коміт>-mac-arm64.zip`         | застосунок macOS, Apple silicon, ad-hoc підпис |
| `Orca-<версія>_overhedge.<k>.g<коміт>-linux-x86_64.AppImage` | десктоп для Linux поза Debian/Ubuntu           |
| `SHA256SUMS`                                                 | sha256 усіх файлів релізу                      |

Не в кожному релізі є всі файли: реліз, що змінив лише сервер чи Linux, може не мати zip для Mac.
Беріть кожен файл з найновішого релізу, де він є. Zip для Mac і AppImage мають власний лічильник
збірок (`<m>`, `<k>`); усі файли одного релізу зібрані з одного коміту.

Завжди перевіряйте завантажене за `SHA256SUMS` (команда є в кожній інструкції).

## Оновлення — лише з цього форку, ніколи з офіційного каналу

У десктопних збірках форку (macOS і Linux) вбудований оновлювач Orca вимкнений, тому вони ніколи
не замінять себе офіційним релізом, який прибрав би патч. «Check for updates» у застосунку нічого
не знаходить, так і має бути. Серверний пакет Orca теж ніколи не оновлює сама.

Щоб оновитися, завантажте новішу збірку зі сторінки Releases і встановіть її так само, як першу.
Не ставте офіційну Orca поверх форку, якщо не хочете піти з форку (див. «Відкат» у кожній
інструкції): чати й налаштування лишаться, але функції форку зникнуть.

У релізах ніколи немає метаданих оновлювача (`latest*.yml`), а оновлювач Orca читає лише
`stablyai/orca`, тож і з цього репозиторію він нічого не підхопить.

## Ваші дані

Форк має той самий app id і ті самі теки даних, що й офіційна Orca
(`~/Library/Application Support/orca` на macOS, `~/.config/orca` на Linux, а також `~/.orca`),
тому перехід між офіційною версією і форком зберігає чати, налаштування й плагіни. Збірка значно
старішої версії апстриму, ніж та, що працювала, може не прочитати дані, записані новішою; спершу
зробіть резервну копію, як показано в кожній інструкції.
